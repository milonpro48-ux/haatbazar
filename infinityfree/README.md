# HaatBazar — InfinityFree PHP/MySQL hosting adapter

This folder is the PHP/MySQL deployment adapter for hosts that do not run the Node.js server. It shares one MySQL schema between the React storefront API and the PHP admin dashboard; it must not be combined with the unrelated `hb_*` tables from `haatbajaar-panels-v3.zip`.

## Included
- `api/index.php`: initial API for listings, accounts, checkout and SSLCOMMERZ callbacks.
- `admin/index.php`: admin dashboard for listings/stock, orders/status, buyer/seller list, seller verification reviews, reports and printable invoices.
- `database/schema.sql`: canonical MySQL schema.
- `database/admin-panel-migration.sql`: additive seller-verification table for existing installations.
- `uploads/.htaccess`: denies direct execution of script-like uploads.

## Install / update on InfinityFree
1. Create the hosting account and domain/subdomain; enable HTTPS.
2. Create a MySQL database in the InfinityFree control panel.
3. For a new install, import `database/schema.sql` using phpMyAdmin.
4. For an existing install, run `database/admin-panel-migration.sql` in phpMyAdmin to add the seller-verification table.
5. Upload the contents of `infinityfree/` to the website root. Upload the React `dist/` build to the same root after configuring the frontend for this API. Keep `config.php` private and never commit it.
6. Copy `config.example.php` to `config.php`; set database connection, public base URL, and SSLCOMMERZ sandbox credentials.
7. Create the first admin user in the `users` table with a `password_hash()` generated by PHP. Never store plaintext passwords.
8. Visit `/admin/` after logging in with an account whose role is `admin`.

## Admin panel status
The admin dashboard uses the existing `users`, `listings`, and `orders` schema. Product creation/editing, stock/status management, order status updates, seller-verification review, user listing, reports and printable invoices are implemented in the panel source. Seller application submission and frontend integration remain separate follow-up work.

## Important limitations before production
- The React frontend is not yet fully wired to all PHP API routes; static GitHub Pages preview does not exercise this backend.
- The current order schema supports one product line per order record. Online checkout currently requires one line at a time.
- Payment, OTP and courier integrations must be validated with real provider sandbox accounts. Do not mark a transaction paid based only on a browser redirect.
- Use HTTPS, a strong private config, verified backup/restore, rate limiting, authorization tests, and provider sandbox tests before live launch.
- Never put SSLCOMMERZ credentials in JavaScript or expose them in GitHub.

SSLCOMMERZ flow requires a server-created payment session and server-side transaction/IPN validation before treating an order as paid: https://developer.sslcommerz.com/doc/v4/index.html
